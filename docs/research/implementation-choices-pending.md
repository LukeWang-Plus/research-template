## 2. 研究行为相关

### D1 调参采样策略与随机性

- **状态**：已确认，已同步正式文档，代码调整已实施。
- **位置**：`core/tuning.py::tune` 的 `optuna.create_study`；`core/runner.py::execute` 的 `seed_all`。
- **当前行为**：没有显式传 sampler，使用 Optuna 默认 TPE，采样器未指定 seed；每个 trial 的训练使用同一个 `config.seed`。
- **影响**：固定训练 seed 不等于固定参数搜索轨迹。重新创建 study、跨进程继续或并行搜索可能得到不同参数序列；并不意味着记录的 trial 结果错误。
- **需确认**：是否明确采用默认 TPE；是否固定搜索 seed、如何与训练 seed 关联；是否接受只保证记录和重跑已选配置，而非完整搜索过程逐步复现。
- **边界提示**：给 sampler 传 seed 本身不保证中断续跑或并行搜索精确复现，不因此默认引入采样器状态持久化或进程管理体系。
- **结论**（Q106–Q110）：
  - 首版采样器仅支持 TPE 与 Grid，默认 TPE，不扩展其他算法或建立采样器注册框架。
  - 采样器复用 `config.seed`，不新增独立搜索 seed；所有 trial 的训练使用同一个配置 seed。
  - 不承诺中断续跑、跨进程或并行搜索与连续串行运行具有完全相同的搜索轨迹，不额外保存采样器内部状态。
  - Grid 的候选复用配置中的 `categorical/choices`，全部搜索参数及有限候选预先列清楚；不自动把连续区间离散化或展开条件搜索。
  - 已选参数后的确定性派生计算可以保留。动态新增搜索参数的条件搜索由研究者选择 TPE；显式选 Grid 却请求未预先列出的参数时明确报错，不自动切换。
  - `--trials` 仍是本次追加预算，Grid 耗尽时提前结束，不为凑预算继续搜索；首次使用展示组合总数。
  - 本项仅确认行为，具体配置字段与 Optuna 接入在实施时采用最小实现。

- **结论**（Q114）：取消数据的 toy 名称/路径以及主指标、优化方向、epoch 上限的隐含默认。用到的字段明确必填，用不到的允许缺席，不提供隐含替代值。正式实验须明确数据身份；本地读取方法要求其所需路径，HF/内存数据不强迫填假路径。默认监督训练要求主指标、方向和 epoch 上限；自定义流程按实际使用的能力要求相关字段，不强迫非 epoch 流程填无用轮数。示例配置显式写出所用值。具体校验位置在实现时采用最小必要方式。

### D3 汇总时设备/硬件是否属于可比性条件

- **状态**：已确认（Q115–Q116），保持克制的现有边界。
- **位置**：`core/analysis.py::rows`、`summary`、`paired`。
- **当前行为**：方法配置中的 `params` 和 `train` 构成训练设置；设备、外部平台开关、输出目录与备注不纳入。数据身份和评估协议另行检查，数据路径不作为身份已确认。
- **影响**：同一方法的 CPU/GPU 运行可合并为多 seed 汇总。对预测质量指标可能合理，对延迟、吞吐量、显存等指标硬件直接影响含义。
- **需确认**：是否保持当前字段边界；性能指标是否由研究者在评估协议中明确环境条件，而不是对所有指标统一强制设备相同。
- **边界提示**：不默认建立硬件指纹或性能基准管理系统。
- **结论**：硬件差异不作为统一比较限制；不增加性能指标或精度的专门比较规则。普通方法参数按已有配置记录和检查；特殊评估设置若改变实验含义，由研究者使用已有协议标识说明，不自动推断。
- **batch size 澄清**：同模型、同数据集而 batch size 不同，可以作为两种设置并列比较、分别多 seed 汇总，并在合理配对设计下做两侧检验；不能混成同一设置的一组重复运行。当前示例 batch_size 位于 params，已有训练设置检查覆盖。不为默认评估另加硬件或精度认证，AMP 仍不内置。
