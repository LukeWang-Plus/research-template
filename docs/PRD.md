# 产品需求

> 状态：首版、此前修复及 D1–D13 已确认调整已实施；实际本地验证与尚未完成的外部验收见 [实施计划](ImplementationPlan.md)，代码完成不等于整体验收通过。 终端展示与显式分析保存已确认、待实施，见第 5.10 节。

## 1. 背景与目标

项目名为 **Research**。公共代码命名与 CLI 约定见 [技术架构](Architecture.md#1-总体组织与目录)。

现有模板设计不合理，接入新方法需要过多手工操作，调参和实验管理能力不足。重构旨在减少研究者的重复劳动，方便记录实验、比较结果，并据此改进研究方法；不将研究模板建设为实验管理平台。

旧重构方案仅供参考，不构成新设计约束。旧方案中的功能、技术选型和首版范围均不自动继承，需在后续讨论中重新确认。

## 2. 使用者与场景

- 面向个人研究者管理自己的实验。
- 可以将模板交给同门，由其独立使用；合作场景也限于可信的师门内部人员。
- 不以团队协作治理、多租户或不可信使用者为设计目标。

## 3. 已确认的行为与安全边界

### 3.1 正确性与错误处理

- 只做必要校验：入口错误，以及容易导致结果看似正常、实际错误的关键条件。不要求每层函数重复防御。
- 错误应明确暴露；不自动修复、猜测参数、纠正数据、跳过坏样本、重试或静默降级，避免擅自改变研究方法。
- 主动启用的功能失败即报错退出。外部实验管理平台仅对 SDK 向调用方抛出的异常执行该规则；SDK 自行处理、吞掉或后台消化的错误不探测、不接管，不承诺远端实时可用或上传成功。研究者可手工移除该平台接入选项后重新启动实验。调参中显式指定的可容忍异常是有限例外，处理规则见第 5.5 节；不等同于吞掉错误或自动修复。
- 接受实验失败与重跑；优先防止静默错误和已有成果的意外损失，不以持续可用或自动恢复为目标。

### 3.2 实验协议与研究者责任

- 默认流程不泄漏测试数据；特殊训练方法允许研究者显式自定义流程。
- 依靠清晰流程与必要检查，而非防绕过的访问权限系统。
- 模板负责自身公共行为和默认流程的正确性，不保证自定义算法合理，也不保证研究者的代码不存在数据泄漏。

### 3.3 文件与覆盖

- 默认不覆盖已有实验目录，不静默复用其内容。
- 用户可显式选择覆盖，例如丢弃报错中断的实验并在原位置重新运行。
- 覆盖表示重新开始，不是恢复训练；不得自动继承旧 checkpoint 或混合新旧配置、指标和结果。
- 覆盖范围仅限目标实验的生成内容，不涉及原始数据、其他实验或用户源码。
- 正在写入的实验不得被另一个模板进程写入或覆盖；用户不必靠手工检查 PID 来避免此类冲突。
- 不承诺覆盖可撤销，不提供默认自动备份或回收机制。
- 接受异常中断丢失最后一段未保存进度；不保证断电、磁盘损坏等情况下仍可恢复。

### 3.4 信任边界

- 使用者、自定义代码以及已确认来源的本地数据和制品视为可信。模板不负责安全运行恶意代码或处理恶意文件。
- 允许正常下载、加载 Hugging Face 等来源的外部模型，不因来自网络而禁止使用。
- 涉及远程代码执行或不安全反序列化时，由研究者确认来源并显式选择；在 baseline 代码中明确传参即可，不需要审批或信任管理系统。
- 模板不得自动开启远程代码执行，也不得在加载失败后自动切换到不安全反序列化。

### 3.5 记录与验证

- 实验记录用于了解做过哪些实验、结果如何，以及帮助后续比较和改进，不是审计证据。
- 不提供防篡改封存、完整行为追踪或审计认证，不证明实际执行完全符合配置。研究者负责不手工篡改产物。
- 精简验证仅覆盖模板自身的正确性，不扩大到研究方法认证；不以完整统一测试套件作为接入自定义方法的强制前提。

## 4. 明确不做

- 代码沙箱、防主动绕过的权限系统、团队治理机制。
- 通用安全序列化框架、制品防篡改和审计认证。
- 自动错误修复、故障降级或损坏修复机制。
- 为覆盖保护引入通用事务、自动备份或复杂进程管理系统。
- 为理论上所有故障建立庞大验证矩阵。

## 5. 首版功能范围

### 5.1 通用性、方法接入与运行入口

- 通用的是实验管理，不是研究数据与算法。文本、时序、图网络等方向可保留各自的数据结构、模型输入、训练算法和指标实现，不做大一统格式。
- 提供可选的常规监督学习训练、验证、测试流程；特殊方法可完全自定义训练循环，仍能按需使用记录、checkpoint、调参和比较等公共能力。
- 不强迫自定义方法实现所有能力；请求未支持的恢复、剪枝等功能时应明确报错，不假装支持。同一 baseline 可以随数据集或研究需求选择是否调参。
- 新增方法不需要修改 CLI 分支或实验管理核心；允许添加方法代码、配置及必要的一处显式名称映射，不要求大量复制脚手架或填写空接口。
- 强化学习可通过自定义流程接入，首版不提供 RL 专用训练器，也不宣称已验证所有研究方向。
- 正式实验通过 CLI 在本地或集群运行。Notebook 可独立调用各项能力，也可调用与 CLI 共用的完整实验入口，先做小规模验证再正式运行。
- Notebook 探索可使用内存模型和数据，不强制注册或创建实验目录；完整实验入口不要求兼容任意内存对象组合。
- Notebook 在当前 kernel 中同步执行，不提供后台提交、重连或退出 kernel 后继续运行的保证。

### 5.2 数据准备与配置

- 提供独立数据准备入口，由研究代码实现预处理和划分；简单实验也可直接读取现成数据。
- 同一任务的多个数据集可转换为任务内约定格式，原始结构相同的来源复用转换逻辑。分词、模型专属图构建等处理按方法需要实现，不强迫所有模型消费相同 Tensor。
- 划分规则由任务决定，不统一假定随机拆分；训练不自动重新划分或重建准备产物。
- 准备好的数据、embedding 或图等产物可显式保存并复用，由研究者负责匹配当前实验；不做通用缓存或自动失效判断。
- 正式实验采用配置文件及少量点路径覆盖，保存完整的实际生效配置；Notebook 完整实验调用使用相同配置。文件格式、校验与路径规则见 [技术架构](Architecture.md#2-配置cli-与路径)。
- 不引入复杂多层继承或配置组合语言。
- 正式实验明确填写 seed 和数据身份；不隐含使用 toy 数据。主指标、优化方向、epoch 上限及本地路径在所请求能力用到时必填，不用时允许缺席，不强迫 HF/内存数据填写假路径或非 epoch 自定义流程填写轮数。设备仍默认 CPU；具体默认值边界见 Architecture 第 2.1 节。

### 5.3 默认训练、checkpoint 与恢复

- 配置一个验证主指标及其 `min` / `max` 优化方向，用于自动选择模型和默认调参目标；其他指标照常记录。
- 允许研究代码计算综合标量作为主指标，不提供多指标组合规则语言或内置多目标优化。
- 每个完整 epoch 结束后更新续训用的 `last`，恢复时从最近完整 epoch 继续；未保存的中间进度丢弃，不提供 batch 中途恢复。
- 续训覆盖模型、优化器、epoch、随机状态、早停以及实际启用的有状态训练组件；状态表示见 Architecture 第 5.4 节。
- 恢复以原实验配置为基础，仅允许调整总 epoch 上限、设备和外部平台选项，并保存当次生效配置。更换模型、数据、优化器或训练超参数应新建实验；加载旧权重开展新研究不算原实验恢复。
- 恢复保留同一实验身份及历次启动记录，比较和绘图只使用实际续训路径上的有效结果，不混入中断片段或重复 epoch；实现规则见 Architecture 第 5.3 节。
- 按验证主指标保留 Top-K checkpoint，`keep_top_k` 默认 1，其中最优模型为 `best`；`last` 独立保留续训状态，不默认保留全部 epoch。
- checkpoint 管理信息与研究状态分离：查询、比较、绘图、历史筛选和定位不得要求反序列化研究状态。默认安全加载；方法可以普通可选函数显式加载可信特殊对象，不自动降级或识别格式。更新使用新状态文件，成功后原子更新管理信息，再清理不再需要的旧引用；允许中断留下未引用文件，不引入事务或自动迁移系统。
- 提供可选早停，默认关闭；开启时配置 patience 与最小改善量，恢复时保留早停状态。改善须严格大于最小改善量，同分不重置耐心；Top-K 与 best 同分优先较早 epoch。早停属于正常完成。
- 默认监督流程不维护累计 batch step；恢复时若已达到配置的 epoch 上限，提示无需继续并正常返回，不新增启动记录或初始化外部平台。上限小于已保存进度仍报错，不替自定义流程猜测完成条件。
- 默认设置 Python、NumPy、PyTorch 的常见随机源并保存 seed；自定义方法负责额外随机源，不承诺跨硬件或依赖版本逐位一致，不提供独立严格确定性模式。
- 自定义训练自行决定恢复边界、所需状态及精度策略，不强迫其复用默认生命周期。

### 5.4 独立测试与结果产物

- 默认训练仅使用训练集与验证集；测试是显式动作，默认加载 `best`，也可指定 Top-K 中的其他模型或外部 checkpoint。
- 对应方法负责模型加载，不自动识别任意格式，也不要求外部 checkpoint 先转换为模板训练记录。
- 来源失败或中断但有有效 checkpoint 时仍可显式测试；测试成功不改写来源训练状态，加载失败不自动换模型。
- 调参不为每个 trial 自动测试；实验组允许选择哪些成员执行测试。
- 每次测试单独保存结果，关联来源实验（如有）、实际 checkpoint、评估配置和数据，不复制整个训练目录。
- 默认新建测试结果；允许显式指定旧结果并覆盖，复用第 3.3 节的保护规则。不得因配置相同自动覆盖，不改动训练记录、来源 checkpoint 或其他测试结果。
- 允许保存逐样本预测及方法专属产物，不强制所有任务采用统一预测格式；提供可选分类图表工具。
- 模板不禁止研究者查看多个候选的测试表现。根据测试结果选择模型会使测试集参与模型选择，实验纪律由研究者负责，不建设正式/非正式权限系统。

### 5.5 调参

- 采用 Optuna 单目标搜索，持久保存 study/trial 和搜索进度，支持显式继续搜索。
- 采样仅支持 TPE 与 Grid，默认 TPE；采样器复用实验 seed，所有 trial 训练使用同一 seed。不承诺中断续跑或并行的搜索轨迹完全复现，不保存采样器内部状态。Grid 仅使用预先枚举的有限候选，不自动离散化、展开条件或切换采样器；具体参数与边界见 Architecture 第 7.4 节。
- 继续同一 study 时保持方法、数据、目标指标和搜索空间不变；可增加预算、调整设备、外部平台选项及可容忍异常设置。改变搜索问题需新建 study，不做跨 study 合并或迁移。继续时 trial 数表示本次追加数量，CLI 与 Python 均要求显式提供，无默认预算。
- 支持显式重试指定失败 trial：以原 trial 已记录参数新建 trial，保留原失败记录和重试来源，从头训练而非断点恢复。若原参数未采样完整，只能固定已记录部分；不自动重试，不覆盖原 trial，也不改变下述失败策略。
- 常见搜索空间通过配置表达，条件参数、派生参数或复杂目标通过研究代码实现。搜索保持方法参数范围，不扩大到数据集或数据处理参数；具体接口见 Architecture 第 7.1 节。
- 仅依据验证结果选择参数；可导出默认最优或手动指定 trial 的完整配置，保留 study/trial 来源关联。
- 导出后由研究者显式启动正式训练或多 seed 实验，不自动训练、测试或继承 trial 权重。
- 提供可选 pruning，默认关闭；策略仅支持 `none` 与 `median`，MedianPruner 参数可配置，实际策略与参数进入生效配置。默认流程可报告中间指标，自定义流程按需接入。被剪枝的 trial 标记为 pruned，不记为失败。策略配置化已落实，字段和参数校验见 Architecture 第 7.2 节。
- 研究者可显式指定可容忍的异常类型，包括明确的显存 OOM：当前 trial 标记失败并记录原因，继续搜索，不修改参数或自动重试。
- 未指定的异常终止当前搜索进程；不要笼统容忍所有 `RuntimeError` 或 `Exception`。已启用的外部平台失败仍按第 3.1 节退出。
- 若异常后无法释放资源或正常继续，不承诺自动恢复进程；并行资源和任务管理不扩展为模板调度系统。

### 5.6 轻量实验组与批量运行

- 多 seed、多配置的每个成员都是独立实验，实验组记录成员关系与状态，用于管理、测试选择和汇总分析，不承担参数搜索职责。
- 组名称、标签、备注默认空，不继承首个成员，需要时可填写。成员保留已有 study/trial 来源并添加 group 关联；手动配置不伪造调参来源，也不表示继承 trial 权重。
- 组级重跑成功清除旧错误，再次失败记录本次错误；成员日志与启动历史不因此清除，显式覆盖成员仍按覆盖语义处理。
- 批量测试仅测试所选成员各自的 best；其他 Top-K 使用单次测试，不增加逐成员 checkpoint 映射。
- 支持串行批量执行与独立单任务 CLI。普通并行由多终端、脚本或 Slurm 安排，调参并行优先复用工具能力。
- 非调参批量遇错停止当前命令，保留已完成结果；修正后显式继续，跳过已完成项，不自动重跑全部任务。
- 独立终端或 Slurm 任务不因其他任务失败而联动停止。
- 继续实验组时跳过已完成成员，正常启动未开始成员；对失败或中断成员显式选择恢复或重新运行，不自动猜测。
- 恢复要求成员具有可用 checkpoint 且方法支持恢复，否则报错。重新运行需明确授权覆盖该失败成员，不影响已完成成员。
- 若成员需要不同处理，先单独处理再继续实验组，不增加逐成员策略配置。此规则不替代调参的可容忍异常策略：调参可记录当前 trial 失败并继续下一个 trial，而非自动恢复或重试它。

### 5.7 本地记录、可选平台与查询

本地记录始终启用，默认保存：

- 实际生效配置、启动参数和 seed；
- 开始/结束时间、运行状态与失败原因；
- 训练/验证指标历史、测试动作的最终结果；
- 训练所需 checkpoint（按第 5.3 节及方法支持情况）；
- 基本环境信息，以及可获取的 Git commit 和 dirty 状态。

不自动复制全部数据、代码和环境，不保存完整代码 patch；方法可额外保存自己的产物。

- 默认监督流程每 epoch 每项指标记录一个点，本地与外部平台统一 epoch 横轴，同轮训练/验证均保留；自定义流程可使用自己的尺度。
- 状态展示区分最后持久化状态与当前活动状态：普通运行可结合写锁派生 interrupted；study 未闭合的启动只能表示活动情况未确认，不断言仍在运行，不自动修复记录或推断失效 trial。具体规则见 Architecture 第 5.5 节。
- TensorBoard、Weights & Biases、SwanLab 均纳入首版，按需启用。本地记录不依赖这些平台，不以外部平台作为读取结果的唯一途径。
- 提供 CLI 列表、筛选与详情查看，Notebook 复用查询能力；实验具有唯一 ID 和可选名称。
- 方法、数据集、seed、状态等已有字段可直接筛选，无须手工重复加标签。
- 训练/自定义运行、测试、调参 study、实验组共用可选标签与自由文本备注，可在创建时填写或事后修改。标签用于筛选，备注用于记录实验目的。
- 单个 trial 复用其运行记录的备注，不维护重复副本；标签和备注不改变配置、执行或结果，不提供评论系统或修改历史。

### 5.8 比较、显著性检验与绘图

- 提供单次实验指标对比、多 seed 均值与标准差、学习曲线，以及 CSV 和图片导出。
- 汇总和检验前检查已有数据集身份 `data.name`，以及研究者声明的任务、数据划分、指标定义及评估方式标识。同名数据集仍须通过协议检查；路径不作为数据身份，不增加哈希、注册或自动识别，研究者负责标识准确性。
- 默认监督流程使用验证主指标选中 epoch 的对应指标；自定义流程使用方法明确返回并保存的最终数值指标字典；独立测试使用该次结果。运行时明确记录来源，比较不通过是否存在验证日志猜测。自定义流程只需已有方法、数据集、协议、seed、参数配置及返回指标即可比较，不强制 epoch、过程日志或 checkpoint；学习曲线另需过程记录。
- 训练记录按有效完成启动的实际训练配置参与比较，不固定读取初始配置。测试的数据与评估协议取本次测试配置，训练设置自动取来源 checkpoint 所属启动的配置；外部 checkpoint 无来源实验时只使用用户明确提供的信息。不把不同训练设置伪装成同一设置下的多 seed 重复实验。
- 不一致时拒绝合并汇总或检验，但允许醒目标注差异后并列表格查看。不同模型或训练超参数本身不是禁止比较的理由。不同 batch size 等训练设置可分别汇总、作为两侧比较，不混成一组重复实验；不增加硬件、性能指标或精度的专门比较规则，特殊语义由已有协议说明。
- 显著性检验仅覆盖用户明确选择的两个方法在多个配对实验上的比较，提供配对 t 检验与 Wilcoxon 符号秩检验，要求显式选择检验类型，不设默认。
- 检验结果统一输出两侧均值和样本标准差、配对数、平均差值、检验名称、双侧约定和 p 值；不自动挑选更显著的检验，也不自动生成方法优越或显著性的结论。
- 输入错误继续报错；已约定的统计退化情况保留描述性结果，将检验标为未计算，p 值为 null 并说明原因，不伪造结果或自动换检验。计算约定、适用前提与输出字段见 Architecture 第 8.2 节；扩展输出和已约定的退化处理已实现。
- 相同 seed 仅是配对标识，不自动证明设计合理；研究者负责配对实验设计。首版不提供逐样本显著性检验或任意多方法两两检验。
- 图表从已保存结果独立生成，无须重跑实验；绘图函数可在 Notebook 中使用，提供默认样式、标题/标签/尺寸等少量参数及 PNG/PDF 导出。
- 学习曲线的阶段与指标均须显式选择；CSV、图片及调参配置导出默认拒绝覆盖，可显式授权仅替换指定输出文件，不改来源或清理目录。图表默认值与接口约束见 Architecture 第 8.3 节。
- 允许通过返回的图对象进一步调整论文用图，不建设复杂主题系统、交互报告或仪表盘。

### 5.9 平台、依赖与示例

- 正式支持 Windows、Linux、CPU 和指定单张 GPU；集群通过 CLI 与调度器脚本使用。
- 首版不内置 AMP 控制、DDP、多机训练或自动 GPU 分配；不限制研究者在自定义流程中实现这些能力。
- 模板仅划分核心依赖与可选辅助平台依赖；不设置文本、图网络、时序等研究方向依赖组。研究者可自行 `uv add` 将需要的依赖加入项目。
- 重构保留现有 PyTorch 固定版本及硬件相关安装来源，不自动升级；具体版本与来源以 [技术架构](Architecture.md#81-pytorch-固定版本与来源) 为准。
- 未启用的辅助平台不强制安装或导入；缺少已请求能力的依赖时明确报错，不自动安装或降级。
- 交付两个最小、轻量、CPU 可运行示例：一个使用默认监督流程，另一个使用不同数据结构与自定义循环，用于学习接入，不迁移现有模型或引入大型资产。
- 提供精简 Notebook、CLI 快速入门和 Bash/Slurm 示例，展示准备、训练、恢复、测试、调参、多 seed、比较与重绘。脚本只负责命令调用、环境和资源设置，不复制实验语义或保证适配所有集群。

### 5.10 面向用户的终端输出与显式分析保存（已确认，待实施）

- 终端面向人阅读，存盘文件面向机器读取。查询和分析默认显示表格与分区摘要，不再将整段 JSON 作为默认终端展示；不增加 `--json` 选项。
- `list` 用于筛选和浏览概览，`show` 用于查看单个实验、study 或实验组详情；比较、汇总和配对检验以适合阅读的表格展示，计算语义及 Python 返回值不变。
- 查询和分析提供显式 JSON 保存，保留已有 CSV、图片及调参配置导出。保存完整返回结果而非屏幕摘要，默认拒绝覆盖，用户可明确覆盖指定文件；不依赖 shell 重定向，不自动保存每次分析或建立分析任务记录。
- 实验配置、过程指标、状态、错误、启动历史和 checkpoint 继续走原有记录路径。不能因终端字段省略、换行或数值格式化损失记录；也不为美化新增第二份指标日志、终端录屏或自动报告。显式导出是用户主动生成的结果快照，不复制整套实验目录。
- 默认训练、自定义训练与独立测试统一提供开始和结束摘要。默认监督训练在交互终端按 epoch 显示进度，非交互环境每个完整 epoch 输出一行文本；测试无进度条，自定义循环不自动推断进度，也不要求新增展示接口。
- Optuna 调参保持其原生输出，不因本次美化叠加逐 trial 的训练展示。失败摘要包含错误，不吞异常、不伪造最终指标；默认监督训练结束展示验证选优结果，而非误用最后一轮结果。
- 不建设交互式 TUI、分页、可配置列、主题系统、通用渲染框架或新记录机制。以本次已确认布局完成一版，后续使用中可微调字段和布局，不再为假设性需求延长讨论。具体展示及导出接口见 [Architecture 第 2.4 节](Architecture.md#24-终端展示与显式-json-导出已确认待实施)。

## 6. 首版验收主线与非目标补充

验收主线：Notebook 探索数据与方法 → 整理代码和配置 → 小规模调用完整入口验证 → 本地或集群 CLI 运行 → 调参并导出选定配置 → 多 seed 正式训练与显式测试 → 查询、比较与独立重绘。

两个轻量示例需展示默认流程和自定义流程都可接入公共能力；新增方法无需改动核心或 CLI 分支。首版包含第 5 节的能力，但不以旧模型数值复现或迁移作为验收要求。

除第 4 节安全边界外，首版不做第二个 PyTorch Lightning、通用 RL 训练器、多目标优化、自动插件发现、Notebook 后台执行系统、通用任务编排或缓存系统。各项取舍以第 5 节相应要求为准。
